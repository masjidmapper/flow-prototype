# flow-prototype

A clickable phone-frame prototype of the MasjidMapper Android app, for reviewing flows before they are built. It runs on mock data only and needs no build: GitHub Pages serves the repo root as it is.

Live: https://masjidmapper.github.io/flow-prototype/ (once Pages is on for `main`, root folder).

## What's in it

- **Prayer** (default tab): location chip, Qibla, the notifications bell and the Profile entry in the top bar; Hijri-first date line; the PrayerHero countdown with the sun path; the Starts / Iqamah table with the tier label and method; the first-run and reminder cards.
- **Masjids**: a placeholder map with the floating search pill (Profile entry, no bell) and the peeking sheet. The real Masjids flow comes later.
- **Saved** (design/11): recent masjids, Your saves with Followed / Saved / + New list, row menus (unfollow, make home, save, add to list), lists you can create, rename and delete.
- **Updates** (behind the bell) and **Profile** (behind the avatar), each opened over the tab you came from.
- A minimal masjid page, so Follow, Save and Save to a list can be tried from outside Saved.
- The inline sign-in sheet with the resume contract: skipping aborts the action, signing in finishes it.

The panel beside the phone (desktop only) switches the demo day, the clock, signed in or not, the home masjid and the theme. Deep links work: `#/saved`, `#/prayer/updates`, `#/masjids/masjid/m-annur`.

## Where things come from

All of it from the `masjidmapper-org/masjidmapper` repo:

| Here | Source |
| --- | --- |
| Screens and rules | `design/00-overview.md`, `design/10-android-ux-overhaul.md`, `design/11-saved-tab.md` |
| `css/tokens.css` | `design/mihrab/tokens.json`, generated by `tools/gen-tokens.py` |
| `assets/masjid*.svg` | `design/mihrab/assets/Icons/` |
| `js/fixtures.js` | `spec/fixtures/prayer/days.json` and `hijri.json`, copied as-is |
| `js/data.js` | invented masjids and announcements shaped like `backend/openapi.json` (`MasjidSetItem`, `FollowData`, `SavedMasjidData`, `ListData`, `AnnouncementResponse`) |
| Visual reference | `android/app/src/test/screenshots/` |

Prayer start times are never calculated here. The two demo days are fixture cases (Wednesday 14 January 2026, Friday 9 October 2026, both Toronto, ISNA, Hanafi Asr). Iqamah and jummah are the home masjid's mock data on the masjid's clock; for Masjid An-Nur on the Wednesday they match the "fixed iqamah for every prayer" fixture exactly. After Isha the countdown uses today's Fajr a day later, which is close enough for a prototype and wrong for the app.

To refresh the tokens after Mihrab changes, with both repos side by side:

```
python3 tools/gen-tokens.py ../masjidmapper
```

## Running it locally

Open `index.html` through any static server (the masjid icon is a CSS mask, which browsers block on `file://`):

```
python3 -m http.server 8000
```

State (follows, saves, lists, the clock) is kept in the browser's localStorage; **Reset prototype** in the panel clears it.
